# Leash Web UI Implementation Plan (Plan 3 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The judge-facing web app: passcode login, chat with Scout (product cards + AG Grid comparison), live approval inbox, AG Grid ledger with refunds, spending-rules editor with Connect PayPal — served by the existing gateway as one service.

**Architecture:** New `web/` package (Vite + React 19 + TypeScript) built to `web/dist`, served by the gateway's Hono app (`serveStatic` + SPA fallback) so the UI is same-origin and authenticates with the owner session cookie. All mutating requests send `x-leash-csrf: 1`. Live updates come from `GET /api/events` (SSE) and trigger refetches. Local dev runs Vite on :5173 proxying `/api` and `/paypal` to the gateway on :8787.

**Tech Stack:** Vite 8, React 19, TypeScript, ag-grid-community + ag-grid-react 36 (Community edition only), lucide-react icons, Vitest + @testing-library/react + jsdom for unit tests. No CSS framework: plain CSS with design tokens.

**Spec:** `docs/superpowers/specs/2026-10-13-leash-design.md` §3.8, §6. Plan 2 final-review gaps (in `.superpowers/sdd/progress.md`).

## Global Constraints

- **Style:** visual language adapted from the "FinTech UI kit | Free (Community)" by *together* (Figma Community): deep purple primary, lime accent, rounded cards, clean sans-serif. Adapt the style only — do not copy screens, artwork, logos or the kit's brand name. No PayPal logo or PayPal look-alike branding anywhere; "PayPal" appears only as plain text where we describe the integration (e.g. "Connect PayPal").
- **Tokens (exact):** `--purple-900:#1E0B4B; --purple-700:#3B1C8C; --purple-600:#5B2EE5; --purple-100:#EEE9FF; --lime-400:#C6F432; --lime-500:#A9DB12; --ink-900:#14121A; --ink-600:#5A5668; --ink-300:#C9C6D3; --surface:#FFFFFF; --canvas:#F6F5FA; --danger:#E5484D; --warning:#F5A524; --success:#30A46C; --radius-card:20px; --radius-ctl:12px;` Font stack: `"Inter", system-ui, -apple-system, Segoe UI, Roboto, sans-serif` (Inter from Google Fonts). Dark mode via `@media (prefers-color-scheme: dark)` plus a `data-theme` override.
- **Security:** the browser never holds API keys; it uses only the HttpOnly owner cookie. Every non-GET fetch sends `x-leash-csrf: 1` and `credentials: 'same-origin'`. Render external links only when the URL starts with `http://` or `https://` (`safeHref`), with `rel="noopener noreferrer" target="_blank"`. Never use `dangerouslySetInnerHTML`. Render Scout's reply as plain text with minimal markdown (bold + line breaks) implemented by splitting text — no HTML injection.
- **Data flow:** SSE `ready` and every `ledger` event trigger refetch of proposals/mandate; refetch proposals after any chat error. A fresh `conversationId` (`crypto.randomUUID()`) per chat session (new on page load and on "New chat"). Chat history lives in client state only.
- **Money:** display cents as `$X.XX` via one `formatUsd` helper; user inputs dollars and the UI converts to integer cents with `Math.round(Number(x) * 100)` after validating `^\d+(\.\d{1,2})?$`.
- **Accessibility:** buttons are `<button>`, inputs have labels, focus states visible, colour is never the only status signal (status chips include text).
- Gateway commands run from `gateway/`, UI commands from `web/`. Existing gateway tests stay green.

### Task 1: Gateway prerequisites for the UI

**Files:** `gateway/src/http.ts`, `store.ts`, `paypal/client.ts`, `scout/gateway-client.ts`, `scout/agent.ts`, `scout/tools.ts`, `server.ts`; tests in `gateway/test/http.test.ts`, `store.test.ts`, `scout-tools.test.ts`.

**Interfaces:**
- `GET /api/session` → `200 { owner: true }` when the request has a valid owner cookie or owner bearer; otherwise `401 { owner: false }`. Not behind `allow()` (it reports auth state).
- `Store.listMandates(): Mandate[]` (newest first; add a `created_at` column via the existing PRAGMA/ALTER pattern, default `datetime('now')`-equivalent ISO string on insert; older rows sort last).
- `GET /api/mandates` (owner) → `PublicMandate[]` (same `publicMandate` redaction).
- `Store.updateMandateRules(id, patch: Partial<MandateInput>): Mandate` — never touches `vaultId`/`setupTokenId`.
- `PATCH /api/mandates/:id` (owner) body = `mandateInputSchema.partial().strict()` (unknown keys such as `vaultId` → 400) → `PublicMandate`.
- `/paypal/return`: on success `302 Location: /?connected=<mandateId>`; on cancel `302 /?connect=cancelled`; error cases keep current status codes.
- Static SPA: `AppDeps.webRoot?: string`. When set, serve files with `serveStatic({ root: webRoot })` from `@hono/node-server/serve-static` for non-`/api` and non-`/paypal` GETs, and fall back to `index.html` for unknown non-API GET paths. API 404s stay JSON.
- Timeouts: PayPal client default `timeoutMs` 10_000; GatewayClient default 75_000; `runScoutTurn` abort 120_000.
- `tools.ts`: when propose returns `auto_approved` or `human_approved`, include `note: 'payment in progress — not complete yet'`.
- `agent.ts`: `SCOUT_SYSTEM` adds "auto_approved and human_approved mean payment is in progress, not complete"; merge the duplicated captured/tracked rule; `SCOUT_FALLBACK_TEXT` = "I ran into a problem finishing that request. If I started a purchase, it's listed below — check its status before asking me to try again."
- `server.ts`: `webRoot = path.resolve(__dirname-equivalent, '../../web/dist')` if `existsSync(join(webRoot,'index.html'))`.

### Task 2: Web scaffold, tokens, API client, formatters

**Files:** create everything under `web/` listed in File Structure except pages/components (stub `App.tsx` rendering "Leash"); root `.gitignore` gains `web/node_modules/` and `web/dist/` (check it already ignores `node_modules/` and `dist/` globally — if so no change).

**Interfaces:**
```ts
// lib/format.ts
export function formatUsd(cents: number): string;                 // 5999 → "$59.99"; non-integer/negative → "—"
export function parseUsdToCents(input: string): number | null;    // "59.99" → 5999, "60" → 6000, "1.005"/"abc"/"-1"/"" → null
export function safeHref(url: string | null | undefined): string | undefined; // only http(s), else undefined
export type Tone = 'success' | 'warning' | 'danger' | 'neutral' | 'progress';
export function statusLabel(s: ProposalStatus): string;  // tracked→"Bought · tracking", captured→"Bought", auto_approved/human_approved→"Paying…", pending_human→"Needs your OK", denied→"Blocked", refunded→"Refunded", failed→"Failed", proposed→"Checking…"
export function statusTone(s: ProposalStatus): Tone;     // tracked/captured→success, pending_human→warning, denied/failed→danger, refunded→neutral, others→progress
// lib/api.ts
export class ApiError extends Error { status: number; code?: string }
export const api = {
  session(): Promise<boolean>,                 // GET /api/session → true/false (401 → false)
  login(passcode: string): Promise<void>,      // POST /api/session (401 → ApiError 'invalid_passcode')
  logout(): Promise<void>,
  listMandates(), getMandate(id), createMandate(input), updateMandate(id, patch), connect(id) → { approveUrl },
  listProposals(mandateId, status?), approve(id), deny(id, reason?), refund(id),
  ledger(mandateId), chat(body) → ScoutTurnResult,
};
```
`request(method, path, body?)`: `credentials: 'same-origin'`, JSON body, `x-leash-csrf: 1` on non-GET, parse JSON error `{ error }` into `ApiError(status, error)`.

**Files:** `web/src/App.tsx`, `pages/Login.tsx`, `components/Sidebar.tsx`, `components/BudgetCard.tsx`, `components/StatusChip.tsx`, `components/EmptyState.tsx`; tests `test/Login.test.tsx`, `test/StatusChip.test.tsx`.

**Behaviour:**

### Task 5: Chat with Scout (products + comparison grid)

**Files:** `web/src/pages/Chat.tsx`, `components/ProductCard.tsx`, `grid/theme.ts`.

**Behaviour:**
- Message list (user right in purple-600 bubbles; Scout left in white cards) + composer (textarea, Enter sends, Shift+Enter newline, max 4000 chars counter). Suggested prompts as chips when empty: "I need an ergonomic keyboard under $60", "Find a USB-C hub for my laptop", "Get me a headset for work calls".
- Send → append user message → `api.chat({ mandateId, conversationId, messages: last 20 })` → append Scout text. While waiting: typing indicator "Scout is searching and checking your rules…" (requests can take up to ~2 min). "New chat" button resets messages and mints a new conversationId.
- Scout text rendered as plain text with `**bold**` → `<strong>` and newlines → line breaks via string splitting (no HTML).
- Each turn's `products` → horizontal row of `ProductCard` (image via `safeHref`-checked `imageUrl` with lazy loading + alt = title, title, brand, cheapest in-stock price, "View" link via `safeHref`) and a toggle "Compare in table" showing an AG Grid (columns: Product, Brand, Merchant, Price, Availability, Category; sortable; price formatted with `formatUsd`; one row per offer).
- Each turn's `proposals` → result card under the reply: title, merchant, price, `StatusChip`, reasons, AI score as "AI match 94%". pending_human → "Review in Approvals" button switching tabs.
- Errors: 502 → inline "Scout is unavailable right now" + refetch proposals; network error → retry button.
- `grid/theme.ts`: `themeQuartz.withParams({ accentColor: '#5B2EE5', headerBackgroundColor: 'var(--purple-100)', borderRadius: 12, fontFamily: 'Inter, system-ui, sans-serif', ... })` with a dark variant; register `AllCommunityModule` once.
- [ ] Implement; add a small test that the markdown-lite renderer never injects HTML (`<img onerror>` text is rendered literally). typecheck, build, commit `feat(web): chat with Scout, product cards, comparison grid`.
